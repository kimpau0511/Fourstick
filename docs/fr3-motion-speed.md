# FR3 시뮬레이션 이동 속도

`GET/POST /v1/sim-demo/motion`의 `speed_percent` 설정 기능은 백엔드에 유지한다. 0~100%, 10% 간격이며 저장값이 없을 때 기본값은 사용자 지정 100%다. dashboard2 시뮬레이션 창·전체화면의 이동 속도 카드는 삭제했다. 0%는 다음 실행을 거부하며 현재 작업이나 STOP 정책을 바꾸지 않는다. `/v1/execute`는 셀 임대를 잡은 뒤 한 번 속도를 확정한다. 모든 home/move와 transfer 자식 프로세스가 같은 값을 쓴다.

팔의100% 속도 한계는 Capability Profile의 URDF 근거 `joint_limits.max_velocity`(3.15 또는3.2rad/s)의80%다. 공식 가속도 수치는 미확보다. 기존 `config/moveit/joint_limits.yaml`의 **시뮬레이션 전용** 파생 규칙 `URDF속도×0.5/s`를 가속도 한계로 쓰며, 팔100%에는 이 한계의80%를 적용한다. 사용자 비율은 속도·가속도 양쪽 한계에 곱한다. 그리퍼100%는 URDF속도0.5rad/s와 파생 가속도0.25rad/s²다. 이 기준은 실기 성능 인증이나 Gazebo 통과 결과가 아니다.

각 관절의 이동량Δq에 대해 정지→정지5차 곡선을 사용한다.

```
u=t/T
q=q0+Δq(10u³−15u⁴+6u⁵)
vmax=(15/8)|Δq|/T
amax=(10√3/3)|Δq|/T²
T=max(최소시간, 각 관절의 (15/8)|Δq|/허용속도,
      각 관절의 sqrt((10√3/3)|Δq|/허용가속도))
```

시작·끝의 위치·속도0·가속도0뿐 아니라 중간의 속도·가속도 극값 지점도 동일한 다항식으로 계산하여 ROS 궤적으로 보낸다. 모든 시간은 같은 T에서 나온다. 위치·속도·가속도를 함께 지정하면 JTC는5차 보간을 사용한다([ROS 공식 설명](https://control.ros.org/jazzy/doc/ros2_controllers/joint_trajectory_controller/doc/trajectory.html)). 경로·충돌·실행 직전 안전 검사는 유지한다.

최소시간 팔0.8초·그리퍼1초는200Hz 제어기의 짧은 동작에 대한 정책 하한이며 설정의 provenance에 근거를 남긴다. 완료 확인 여유는 기존20초를 유지한다. ROS 결과 대기는T+여유이며, 시간이 지났다는 이유로 성공하지 않는다. terminal 성공 결과와 유효한 실제 목표 관절 관측을 요구한다. 그리퍼 열림·닫힘은 실제 관절값으로, 물체 파지는 기존 시뮬레이션 fixture/자재 위치·추종/해제 관측 계약으로 확인한다. 물리 파지 센서의 실기 관측으로 주장하지 않는다.

## 미검증 범위

가변 시간·5차 궤적 전체의 Gazebo 추종 오차, 실제 속도·가속도, 그리퍼 파지/해제, 자재 추종·안착 및 정지/복구 회귀는 아직 이동 시험 전이다. 특히100%를 검증 완료로 사용 가능하다고 보고하지 않는다. 기존 기록에는 짧은1.5초 동작의 PATH_TOLERANCE_VIOLATED 사례도 있으므로 수학적 제한 통과가 컨트롤러 추종 통과를 대신하지 않는다. 시험한다면 먼저 범위를 보고하고,50% 소이동→최대 관절 이동→단일 자재 이송→더 높은 비율 순서로 관측한다. 이번 작업에서는 실제 이동·STOP 없이 대역 테스트만 수행한다.
