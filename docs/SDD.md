# SDD 절차 (Spec-Driven Development)

팀이 Claude·Codex 어느 쪽을 쓰든 **이 문서 하나**를 따른다. 도구별 명령(`/spec`, Codex skill `sdd`)은
이 문서를 가리키는 진입점일 뿐, 절차를 따로 적지 않는다.

## 언제 쓰나

| 작업 | 방식 |
|---|---|
| 안전 동작·API·계층 계약을 바꾸거나, 동작이 모호한 새 기능 | **SDD** (이 문서) |
| 버그 수정, 동작이 명확한 작은 변경 | **TDD** — 재현 테스트 먼저, 재발하면 잡히는 테스트를 남긴다 |
| 오타·주석·문서 | 바로 수정 |

## 5단계

| 단계 | 주도 | 하는 일 | 산출물 |
|---|---|---|---|
| 1. 설계 | 사람 (AI 보조) | `docs/PRD.md`·`docs/ADR.md`·`docs/ARCHITECTURE.md`와 관련 코드를 읽고, 5가지 질문(무엇·왜/성공 기준·제약·경계·엣지 케이스)에 답한다. 코드·문서로 답할 수 없는 건 사람에게 묻는다 | `specs/<기능>.md` 앞부분 |
| 2. 단계 분해 | AI (사람 승인) | 같은 스펙 파일의 "구현 단계"를 템플릿의 단계 설계 원칙대로 쓴다 | `specs/<기능>.md` 구현 단계·상태 표 |
| 3. 구현 | AI (사람 검토) | 단계마다 테스트 먼저 → 구현 → 수용 기준 실행 → 상태 표 갱신 | 코드·테스트, 갱신된 상태 표 |
| 4. 리뷰 | 사람 + 다른 모델 | 아래 리뷰 규칙대로 대조·교정 | 반영된 수정 |
| 5. 환류 | 사람 + AI | 아래 환류 규칙대로, 바꿀 게 있을 때만 | 테스트·문서 갱신 |

### 승인 게이트

- **스펙(1)과 단계(2)를 한 번에** 사람이 승인한다. 승인 전에는 구현하지 않는다.
  스펙 파일 작성·`specs/README.md` 갱신은 승인을 받기 위한 초안이라 안전 관련 기능이어도 승인 전에 해도 된다.
  코드·설정·다른 docs는 승인 전에 바꾸지 않는다.
  준비 체크리스트가 하나라도 비어 있으면 승인 요청을 하지 않는다.
- 구현 중 단계의 **추가·삭제·순서·범위**가 바뀌면 다시 승인받는다. 승인된 범위 안의 세부 구현 선택은 재승인하지 않는다.

### 구현 규칙

- **단계가 3개 이상인 스펙은 단계마다 새 세션**에서 시작한다. 새 세션은 대화 기억 없이
  `AGENTS.md` → 해당 스펙 파일(단계 + 상태 표)만 보고 시작한다. 그래서 단계는 자기완결이어야 한다.
  (긴 세션에서 여러 단계를 이어 돌리면 컨텍스트가 커져 뒤 단계 품질이 떨어진다.)
- 한 번에 한 단계만 돈다. 두 단계를 동시에 돌리지 않는다(상태 표 충돌).
- 수용 기준은 둘로 나눈다.
  - **자동 검증**: 실행 명령과 기대 결과. 에이전트가 직접 실행한다.
  - **사람 확인**: Gazebo·MoveIt·vLLM·브라우저가 필요한 검증. 필요한 환경, 확인할 관측 결과,
    남길 증거(로그 경로·스크린샷 등)를 적고, 확인 전까지 상태는 `사람 확인 대기`.
- 단계를 끝내면 그 세션이 상태 표에 상태와 한 줄 요약(생성·수정한 파일, 핵심 결정)을 쓴다.
  다음 단계 세션은 이 요약을 인계 정보로 쓴다.
- `claude -p`·자동 실행 스크립트로 단계를 돌리지 않는다(API 과금).

### 리뷰 규칙

- 대조 항목: 스펙 수용 기준 · `docs/ADR.md` 결정과 충돌 여부 · `AGENTS.md` 안전 불변식 ·
  PRD·ARCHITECTURE·ADR 갱신 필요 여부.
- **구현한 모델과 다른 모델의 리뷰가 필수**인 변경: AGENTS.md 크기표의 "큰 변경"(안전 정책·로봇 구성·아키텍처),
  그리고 `core/`·`validation/`의 안전 경로 변경. 나머지는 권고.
- 다른 모델을 쓸 수 없으면(토큰 소진 등) **사용할 수 있는 가장 성능 높은 모델로 리뷰를 이어간다.**
  이때도 구현 세션과 분리된 새 세션에서 한다.
- 리뷰 지적은 **코드 원문(file:line)과 대조한 뒤** 반영한다. 리뷰어도 틀린다.

### 환류 규칙

바꿀 게 있을 때만 한다. 회고 문서를 따로 만들지 않는다. 재발 방지는 가장 좁은 위치에 넣는다.

| 무엇이 드러났나 | 어디에 |
|---|---|
| 재발할 수 있는 결함 | 회귀 테스트 |
| 요구사항·범위 변경 | `docs/PRD.md` |
| 구조 변경 | `docs/ARCHITECTURE.md` |
| 새 결정 또는 결정 번복 | `docs/ADR.md` |
| 스펙 양식의 부족 | `specs/_TEMPLATE.md` |
| 모든 작업에 해당하는 규칙 | `AGENTS.md` "배운 점" 한 줄 (사람 승인 후) |

## 도구별 실행

| | Claude Code | Codex |
|---|---|---|
| 시작 | `/spec <기능 설명>` | skill `sdd` 또는 "docs/SDD.md에 따라 <기능> 스펙을 써줘" |
| 단계마다 새 세션 | 서브에이전트(Agent 도구)에 단계 하나씩 — 메인 대화 기억 없이 새 컨텍스트로 시작하므로 새 세션과 같다. 또는 새 세션 | 새 세션 또는 `codex exec` |
| 다른 모델 리뷰 | Codex: `codex review --uncommitted` | Claude Code 새 세션 |
